# Thick Shift 3D

Midnight at the Mascot Depot. A co-op night-shift survival game in first person: walk the building with a torch, keep its wiring alive, and stay out from under the very large retired mascots until 6 AM.

## Run it

The repo is a pnpm workspace. The game is TypeScript in `packages/game/src/`, and each app in `apps/` runs it somewhere: the web or a Discord Activity. The web and Discord apps are Vite builds. three.js and the Discord SDK come from npm and are bundled, and Cloudflare's Vite plugin runs each app's Worker inside the dev server.

It needs Node 22.18 or later (`.node-version` names the one CI uses) and the pnpm that `packageManager` in `package.json` pins. `corepack enable` sets that pnpm up.

```sh
pnpm install
pnpm dev                 # the web game and its Worker, on localhost:5173
pnpm dev:discord         # the Discord Activity and its Worker, on 5173 too (the next free port if the web game has it)
pnpm build               # build both apps into apps/<app>/dist
pnpm run deploy          # build and publish the web game (plain `pnpm deploy` is a pnpm command)
pnpm run deploy:discord  # build and publish the Discord Activity
pnpm typecheck           # tsc -b over every package's projects
pnpm test                # Vitest on packages/sim: the map, the floor plan and seeded nights
pnpm lint                # Biome's lint rules and import order (--write to fix)
pnpm format              # reformat everything with Biome
pnpm format:check        # fail if anything is not formatted
```

The game, the simulation, the apps and the balance tools are TypeScript. Vite strips the types without checking them, and `pnpm typecheck` checks them. The compiler options every project shares are in `tsconfig.base.json` and the lint rules in `biome.jsonc`, each with its reason beside it. GitHub Actions runs the typecheck, the lint, the format check, the tests and both builds on every pull request and every push to `main`. Biome reformatted the whole repo once, in a commit of its own, and `git config blame.ignoreRevsFile .git-blame-ignore-revs` makes `git blame` skip it.

Rooms need the Worker. `vite dev` runs it, Durable Object and all, so starting and joining a room work locally, and the page reloads when the game's code changes. A build's `apps/web/dist/client/` is the whole static site, and any static server that serves it at the root of a domain runs the game solo: with no room to reach, the page runs the night itself. The page loads its scripts from `/assets/`, so it does not work from a sub-path.

Add `?dev` to the URL for the dev menu (the backtick key, or the Dev button on the pause screen and in the touch menu): god mode, infinite power, freeze, wake every mascot, game speed, forced rot stage and dread, time skips, power and torch buttons, and per-mascot controls. Anyone in the room can use it: each control sends a dev command that whoever runs the night checks and applies (`devFloor` in `packages/sim/src/session.ts`), so everyone sees the change. Add `?debug` to get `window.ts` (the live `game` and `client` state) in the console.

`packages/game`, `apps/web` and `apps/discord` each have three TypeScript projects: `tsconfig.json` for the browser code, `tsconfig.worker.json` for the Worker and `tsconfig.node.json` for the Vite config, which runs in Node.

An app imports the game only by the names `packages/game/package.json` exports (`@thick-shift/game`, `@thick-shift/game/state` and so on), never by a path into `packages/`. The game imports the simulation the same way, as `@thick-shift/sim` and its subpaths. The Node tools are the exception: they import `packages/sim/src/` by path, since `tools/` is not a package. An app changes how the game starts and what its title screen and lobby offer through `platform` in `state.ts`, set before `start()` (the Discord app does it in `src/activity.ts`). `fixedRoom` means the room comes from outside, and everyone opens the same one: the first to arrive starts it and the rest join. `title` replaces the title screen, and `invite` replaces the room code and link in the lobby. The web game leaves all three alone.

## Discord Activity

`apps/discord` runs the game as a Discord Activity, deployed as its own Worker (`thick-shift-discord`). It is a Vite app like `apps/web`, with `terms.html` and `privacy.html` as two more pages beside `index.html`. Discord adds `frame_id` to the page's URL, and the app's `src/boot.ts` imports `src/activity.ts` when it sees it. That import is a separate chunk with the SDK in it, so opened anywhere else the page never fetches the SDK and plays as the web game does. Everyone who opens the Activity in one channel shares Discord's `instanceId`, so that becomes the room (`d-` and the id) and nobody types a code. Each player presses Clock in, which opens the room. The first to arrive starts it, and the rest join. Names come from Discord through an OAuth sign-in. The Worker trades the code for a token at `/api/discord/token`, so the client secret stays on the server. A player who declines the sign-in plays as Guard.

Discord only lets the page reach its own origin. The SDK is `@discord/embedded-app-sdk` from npm, bundled into the build, so it comes from that origin like the rest of the game. The stylesheets and fonts stay on their pinned CDN links in `index.html`, and the Discord Worker rewrites those links to `/ext/...` as it serves the page, then fetches them from jsdelivr and Google Fonts itself. Vite renames the built page's scripts and stylesheet with hashes and leaves the CDN links as they are. `run_worker_first` in `wrangler.jsonc` sends `/` and `/index.html` to the Worker before the static files, so the Worker rewrites the built page on its way out. Only the catppuccin-neu stylesheets and Google's font files pass through it.

To set it up:

1. In the Discord Developer Portal, create an application. Under Activities > Settings, enable Activities (and iOS and Android if wanted). Under OAuth2, add a redirect such as `https://127.0.0.1`. The SDK needs one but never uses it.
2. Put the application ID in `vars.DISCORD_CLIENT_ID` in `apps/discord/wrangler.jsonc`. Then, in `apps/discord`, run `pnpm wrangler secret put DISCORD_CLIENT_SECRET`, and from the repo root run `pnpm run deploy:discord`.
3. Under Activities > URL Mappings, map `/` to the Worker's host with no protocol, for example `thick-shift-discord.<account>.workers.dev`.
4. Start the Activity from a voice channel. Until the app is published, only its owner and team members can launch it.
5. To verify the app, put `https://<worker host>/terms` and `https://<worker host>/privacy` in General Information as the Terms of Service and Privacy Policy URLs (`apps/discord/terms.html`, `privacy.html`). If the game starts collecting anything new, update `privacy.html`.

To test from your own machine, run `pnpm dev:discord` behind a tunnel such as `cloudflared tunnel --url localhost:5173`, and map `/` to the tunnel's host. Vite turns away hosts it does not know, so `apps/discord/vite.config.ts` allows `.trycloudflare.com`; add your own tunnel's domain there if it is another. Put `DISCORD_CLIENT_SECRET=...` in `apps/discord/.dev.vars`, which git ignores.

## How the pieces talk

The room runs the night. Every player's page holds a WebSocket to `/room/CODE` on the same origin, which reaches that code's `Room` Durable Object in `packages/game/worker/room.ts`. During a night it steps the simulation (`stepFloor` in `packages/sim/src/sim.ts`) ten times a second and sends the full state `S` to everyone. Between nights nothing runs, and it sends `S` whenever it changes. Pages never change `S`. They send commands through `net.send`: actions (`p` for where they are, `use`, `call`, `throw`, `name`), `go` to start the next night, and the dev menu's cheats. The room applies them with `commandFloor` (`packages/sim/src/session.ts`), which checks every field. Nothing is peer to peer, so it works on any network that allows WebSockets, and no player's tab or connection can hold up anyone else's night.

A page opens a room with `?mode=make` (a new code; if it is taken, the page draws another), `join` (a code someone typed; refused if the code has no night, and a night everyone left is kept for 5 minutes) or `either` (Discord's fixed room, and a page coming back after losing its connection). Everyone in a room can press the button for the next night, and the first press starts it. A page without `v=2` in its URL is refused with 4426. Pages from this version on ask the player to reload. Pages from before it don't know the code, so they fall back to solo or say the connection failed.

The room saves `S` to its storage whenever it changes between nights and every two seconds during one, so the object can sleep between nights and a deploy doesn't end a night. A fresh object reads `S` back and rebuilds what the mascots were thinking with `adoptFloor`, and each guard gets their place back when their page reconnects. A room everyone has left keeps its night for 5 minutes, then deletes it. If a page can't reach a room when it starts one or opens Discord's, or loses the room it was in and can't get back, it runs the night itself with only its own guard, using the same `session.ts` and `adoptFloor`. A page that can't join a typed code says so instead.

`main.ts` loads `three/app.ts`, and with it three.js, the first time a night is drawn, so the title screen and lobby come up without waiting for it. Vite builds it, and `dev.ts`, as chunks of their own.

## Winning

A run is five nights (`FINAL_NIGHT` in the sim's `config.ts`). Surviving a night sets `S.phase` to `'win'` and offers the next one; surviving the last sets it to `'won'`, which shows the run's tallies (`S.total`, `S.deaths`). Everyone flat at once sets `'dead'` and retries the same night, so the tallies carry across attempts.

## The rules

Everything in this section is in `packages/sim/src/sim.ts` unless it says otherwise. `map.ts` beside it is the building as data, and the room uses it too: rooms, doorways, where the breaker boxes and batteries are, what can be walked on and seen through, and how to get from one place to another.

A night is six hours of 70 seconds (`F.HOUR`). Faults break out in the twelve breaker boxes round the building (`BOXES` in `map.ts`, `breakOut` and `stepFaults`, tuning in `FAULT`). A guard alone gets one about every 50 seconds, a little sooner each night and each hour; each extra guard adds half of that again (`FAULT.crew`). A fault never breaks out within 4 metres of a standing guard, and a mascot banging on a shut booth door shorts the box in the room outside that door a third of the time, so hiding in the booth makes work. `S.faults` has one entry per box: `null`, or `{ k, at, burnt }`. Any guard can fix any fault. (Giving each fault to one guard was tried in the harness: alone it made no difference, and crews of two to six won a third to half as often, because they crossed the building past each other instead of each taking the nearest.)

An open fault does three things, worse the longer it is left:

- It leaks power, from 0.02 to 0.1 points a second over 50 seconds (`FAULT.leak`, `ripen`), times `1 / guards` so a crew leaks what a guard alone does.
- After 25 seconds its room's lights go (`darkRoom`). Mascots in a dark room move 15% faster, see a guard with their torch off at 5 metres instead of 12, and the room's lamps in `light.ts` drop to a stutter.
- After 65 seconds it burns (`faultLeft`, the `burn` event): 0.2 points of ceiling a second (times `1 / guards`) for as long as it stays open. The ceiling is `S.cap`: the most the building can hold for the rest of the night. The crank cannot lift power above it. That is what stops a crew ignoring the faults and cranking instead.

Fixing one is a minigame (`three/task.ts`), opened by pressing use at the box: flip the tripped breakers in the order on their tags, join four wires to their colours, or hold a valve open with the needle in the green. `F.FIX` is how long each takes a steady hand (1.8, 2.4 and 2.2 seconds) and is what the harness's guards hold use for. The panel covers the bottom half of the screen. The room stays in view above it and the mouse still looks, but the guard cannot walk, and their torch hangs at the floor and holds nothing (`act: 'fix'`, `beamOn`). X or Esc lets go. The room is only told when the job is done (`{ t: 'use', what: 'fix', i }`), and checks the guard is in reach. A fix is loud: the clunk of the breaker and the lights coming back, and anything out and nearby may come to look.

Power also goes on standing still (3 points a minute, more each night, `DRAIN` and `WEAR`), on each shut booth door (11 a minute), on charging a torch, and 2.5 for every bang on a shut door. A crew pays less for each door, bang and torch on the dock, `2 / (guards + 1)` of a lone guard's price (`crewDraw`): two thirds for two, two fifths for four. One guard at the generator, in the booth beside the charger, puts back 0.7 a second (`CRANK`). There is one handle, it roots whoever is on it, and it is loud: half the time a wandering mascot picks where to go next while the crank is turning, it heads for the booth.

At zero the power is out (`S.out`). The booth doors open, the lights and the charging dock go dead, every mascot gets up, and none of the limits below apply: all four hunt at once, faster, and do not go home. `S.power` stays at 0 until someone has cranked `F.RESTART` back in, which is 20 seconds at the handle in the dark (`S.restart` is the progress, 0 to 1). If the ceiling has fallen under `F.RESTART` it never comes back.

The torch is the one thing a guard has. A full one is 65 seconds of light (`F.BAT_LIFE`). The dock in the booth fills it in 15 seconds and costs the building the same power per torch as it always did, a spare battery adds half, and a guard who is flattened loses half of what was in it. There are three batteries around the building plus one per guard, and a taken one turns up somewhere else half a minute later. A beam on a mascot within 12 metres holds it by how far it has rotted (`LIT_SPEED`): stage 0 stops dead, stage 1 keeps a fifth of its speed, stage 2 keeps two fifths. Rot follows the night and the hour (`rot`). Left alone they stay whole through night 1 and are fully rotten from 3 AM on night 5. Torchlight is what really rots them: every second of beam and every bang on a door adds to that mascot's rot (`m.ire`, `GLARE_PER_IRE`). On night 1 about 25 seconds of beam on one brings out stage 1 and 35 to 50 seconds stage 2, so a crew that lights up everything meets the worse forms early, and the more it leans on its torches the less they do. One standing in its place is switched off and a torch does nothing to it.

The phone is a map, held up with C (`player.me.ph`, sent as `ph` in the `p` action). It runs on the torch's battery at four times the torch's rate (`F.PHONE`), so a full battery lasts 16 seconds with only the phone up and 13 with the torch on too. While it is up the guard cannot run and walks at 60% (`F.PHONE_WALK`, in `player.ts`), and the torch hangs at the floor and holds no mascot (`beamOn`). The room drops it when the battery runs dry or the guard goes flat. It is for a glance: two seconds cost an eighth of a battery. The balance harness's guards never use it.

The mascots come in waves (`turnWave`, `S.stir`). They stand where they stand, stir for half a minute to a minute, walk the rooms, then go back, and the building is quiet for 15 to 40 seconds. Nothing moves for the first 34 seconds of night 1. `heat` is how bad the night is, from 0 to 1. Later nights, later hours, ceiling burnt by faults and bigger crews raise it, and it stretches the waves, shrinks the calm between them and draws the wanderers toward the guards. Two more limits come from it: `roster` is how many may be out of their places at once, and `pack` is how many may be after the guards at once. A guard alone meets two at a time, three late on nights 3 to 5, and is hunted by one. A crew of four meets all four and is hunted by two, three from about 3 AM on night 5. The crew's share of `heat` grows with the square of the extra guards. One that sees a guard while the pack is full stops and stares for a few seconds and goes back to what it was doing.

A wandering mascot sees a guard inside 10 metres, 14 if their torch is on and 5 in a dark room with it off (`SIGHT`), and only in front of itself. It stops and stares for 1.2 seconds (the `spot` event), then comes. A hunt ends in one of three ways. It touches the guard. It loses sight of the guard for four seconds and searches where it last saw them. Or the guard gets into the booth and shuts the door, and it bangs on the door three times (four from night 3), walks home looking at nobody, and stays there 18 to 30 seconds. A torch beam holds one still without wearing it down: when the battery dies it is still there, still coming. Walking into one always counts, hunting or not.

A hunt does tire all of them but Biggs (`TIRE` in `sim.ts`). Eight seconds of hunting empty a mascot's breath. Winded, it comes on at three fifths of its speed, which is slower than a guard walks, for the six seconds it takes to get enough breath back, and what it has then lasts under five. So a guard who keeps moving away from Flan, Squish or Stompy gets clear in the end. The breath comes back whenever it is not hunting at full pace: roaming, searching, standing, stunned, or held in a torch beam. Stompy's charge costs none, and with the power out nothing tires. The clients are not told: a winded one's steps and footfalls slow because they follow its real speed.

Each is a different problem:

- Big Biggs is slower than a walking guard, hunts half as long again as the others, and keeps knowing where his guard is for four and a half seconds after losing sight of them. He cannot be shaken round a corner, only outwalked, and he is the one that never gets winded.
- Madame Flan crawls while any guard is looking her way and runs when nobody is, faster than a guard can walk. The torch is not needed to slow her. Turning your back is the mistake.
- Squish is quicker than a walk and the only one that goes into the ducts with the lights on, where it is quicker still. (With the power out the others find their way through them too.) It comes for whoever is sitting in the booth, by the vent if it is open, and it gets up for anyone who goes into the ducts, at any hour of any night.
- Stompy walks slowly until it sees a guard down a clear run from more than six metres off. Its sight ends the window, so that is up to 14 metres at a guard with their torch on and 10 at one in a lit room with it off, and one in a dark room with it off is never charged. Then it roars, winds up for a second and a half, and charges in a straight line at more than twice a guard's walk. It does not steer and a torch does not stop it. If it hits a wall it is stunned for four seconds. Step out of the line, or do not be in a corridor.

Alone, Biggs and Flan are there from night 1, Squish from 3 AM that night and Stompy from night 4 (`WAKE`). Each extra guard brings them two hours sooner. They are slowest on night 1 (`KEEN`).

A mascot within 1.25 metres with no wall between has you (`F.CATCH`). Furniture does not count as a wall. For a guard tucked in where it does not fit, a mascot walks to the nearest place it does (`standNear` in `map.ts`), and from within 2.6 metres of a guard who stays put it reaches over after 1.2 seconds (`F.GRAB`), so there is nowhere in the building to stand that they cannot get to. The harness checks that against the furniture in the sim's `dressing.ts`. Within that reach it also sees over the furniture, and stepping out of its sight behind a prop does not stop a reach that has begun. A hunt that still gets nowhere is given up after eight seconds, and the mascot leaves that guard alone for ten (`STUCK`).

A flattened guard stays on the floor until another guard stands over them and holds use for three seconds, and then has four seconds in which nothing can touch them. The mascot that did it does not wait by them for whoever comes to peel them up. It goes back to wandering, and the first place it walks to is in another room, at least eight metres from them (`AWAY`). It still comes for any guard it sees on the way, and with the power out it goes for a guard who is still standing. For 1.8 seconds after a catch (`CATCH_GAP`) that mascot cannot catch anyone else or open a locker, so the guard standing next to the one it got has time to run. The others can. Everyone flat at once ends the night, which for a guard alone is the first touch.

Lockers are the one place to hide. Every locker outside the booth is one (`HIDES` in `map.ts`, read from the lockers in `dressing.ts`): three in the West Hall, two each backstage, in the Main Hall, the Kitchen, the Snack Bar and the East Hall, and one each on the Storage Stage and in the Arcade. Most stand by a breaker box or a few steps from one of the booth's side doors, where a guard is when something finds them. Holding use for a fifth of a second at one (`F.HIDE_HOLD`) steps a guard in, and a tap steps them out. One guard to a locker. Inside, the guard cannot move, the torch is off, the phone still works, and the view is out through the door slats, turned no more than about 50 degrees either way. Stamina comes back. Nothing sees, hears, lights or walks into a guard in a locker, and the wanderers do not head for one. A mascot does find them four ways (`openLockers`, `seenHiding` and `lockersNear` in `sim.ts`):

- It saw them get in: one that could see the guard at that moment (`canSee`), which includes one close behind them whichever way it faces. It goes to the locker's doors and opens them as soon as it arrives. Nothing else gives a locker away. One that was hunting them and lost sight before they stepped in does not know which locker, even in the 1.2 seconds (four and a half for Biggs, `RELENT`) that it still knows which way a guard on the floor went. It goes back to where it last saw them (`b.saw`) and searches from there.
- It checks. One that loses the guard it was hunting searches, and may first look in a locker within six metres of where it last knew they were: each one at three chances in ten, nearest first, one at most (`CHECK`). It walks to the doors and yanks them open, empty or not (the `check` event for an empty one). So hide further than that from where it lost you.
- It sniffs: it stands within 1.6 metres of the doors for three seconds (`SNIFF`), for any reason. A wanderer passing by is fine. One that stops there, or is searching there, is not.
- The doors are loud. Getting in or out is a noise of six metres at even odds (`LOCKER_NOISE`), so anything wandering nearby may come and search right outside.

A guard pulled out is not caught on the spot. The `found` event fires, the guard is back on the floor in front of the doors, and the mascot stands for 0.6 seconds in which nothing can touch them (`ESCAPE`). Then it hunts them like any other. For eight seconds after that their hands shake: getting into a locker bangs its doors, a noise heard 24 metres off (`LOCKER_DIN`), and whatever opens that locker has them at once, with no head start. Nothing on screen says so. Stepping straight back in is how you get caught. A guard a mascot reaches with their hands in a breaker box gets the same start (`startle` in `sim.ts`, and the `startle` event): the panel shuts with the job not done, nothing can touch them for 0.6 seconds, and the mascot hunts them. Their hands shake for the same eight seconds, and shaking hands earn no start at a box or in a locker, so only a fix begun after the shaking stopped earns the next one (`p.fixAt`). The box has to have an open fault and be in reach. With the power out the mascots come to where the guards are, as they always do in the dark, and a locker does not hide that: they walk to its doors and stand there until they open it. So a locker is for breaking a chase once round a corner, not for waiting out the night: the clocks keep coming due.

A Mini Biggs is the one thing a guard can throw (`TOY`). It is a palm-sized plush of Big Biggs on a keyring, from the gift shop, with a voice box that sings "Happy Birthday from Big Biggs!". Each guard clocks in holding one (`p.toy`) and can hold one at most. Its own cell died years ago, so it sings on the torch's battery: a throw costs 0.2 of a full battery, one of the five bars on the HUD, which is 13 seconds of torchlight or 3 seconds of phone, and it cannot be thrown on less. G, the right mouse button, RT or the Biggs button throws it where the guard is looking: as far as the floor the view meets, or 14 metres when looking level or up. It flies at 11 metres a second over the furniture and stops short of a wall or a shut door (`landing`). The guard's browser sends only the direction and the distance (`{ t: 'throw', yaw, d }`), and the room throws from where it has the guard and takes the battery, never from a locker and never with hands in a breaker box. Where it comes down it sings for three seconds, and the mascots put that first (`sing`): each one within 12 metres that is wandering, searching or hunting drops what it was doing, nine times in ten, and walks to it. On the way, and for the four seconds it stands over it (`TOY.linger`), it sees and hears nothing else, though walking into it still gets a guard flattened. One that is winding up, charging, stunned or banging on a door pays it no attention, and neither does one on its way home or standing on its mark. A throw that hits a mascot does more (`flyToys`): a toy whose flight passes within 0.3 metres of one's edge (`TOY.hit`) drops at its feet, and that mascot is stunned for five seconds (`TOY.stun`), a charging Stompy included, while the toy sings there for the others. It misses one standing on its mark or banging on a booth door, and it does not hit through a wall or a shut door. The room says so with a `bonk` event. The toy has to fly 4 metres before it touches the mascot (`TOY.armed`), which puts the mascot about 5 metres off or more. One it reaches sooner it flies past, and it lands and sings as usual, so a throw at your own feet stuns nothing. With the power out a toy does less, and the crank is still the only way out of the dark: a mascot that is hunting, winding up or charging does not turn for the song and a thrown toy sails past it, and one that is wandering or searching goes to the song with its eyes and ears open and hunts the guard it sees on the way. For 15 seconds after a song takes it or a toy hits it (`TOY.wise`), a mascot falls for neither: a thrown one sails past it and a song does not turn it, so no crew can keep one stunned for more than a third of the time. Then it lies there (`S.toys`) until a guard with empty hands stands over it and presses use (`{ t: 'use', what: 'toy', id }`, decided by the room like everything else). Anyone's will do. Or there is the gift shop's carton of them on the booth floor by the coat rack (`TOY_BOX` in `map.ts`): six in it at clock-in (`TOY.box`), shared by the whole crew, and one for a tap of use with empty hands (`{ t: 'use', what: 'carton' }`). It is not restocked until the next night, and the ones left sit in it, so a glance says how many. So a Mini Biggs takes a wanderer off the way to a fault, ends a chase for long enough to get out of sight, or stops the one about to reach you, but the next throw means walking to where you sent the mascots or back to the booth, and the bar it cost is light you will not have to hold the next one off. Every screen draws them in the air and on the floor (`actors/plush.ts`).

The booth has three doors, and each button works from both sides of the wall, so nobody can be shut out. A door will not shut on anyone standing in it, guard or mascot. The wall map shows every mascot that is out of its place while the power is on.

## Balance

`node tools/balance/floor.ts` plays every scenario 40 times through the real sim and map in `packages/sim` and prints a table (`--seeds`, `--only`, `--deaths` and `--trace` are explained at the top of the file). It is TypeScript that Node 22 runs by stripping the types; the guards and scenarios are in `harness.ts`. The guards walk with `route()` and `slide()` at the game's speeds, react a quarter to most of a second late, and only know what a person could: what is lit and in front of them, what is close enough to hear, the HUD, the wall map from the booth and a flat teammate's call. Careless, competent and expert guards play alone and in crews of 2, 3, 4 and 6. Then come the strategies that must lose: the booth sealed, one cranking while the rest hide, torches from a corner, ignoring the faults, one runner for three who stay in, camping the charger, kiting a loop, standing in the ducts or the vent doorway, sitting in lockers all night, and standing at a box with hands in it. The `hides` scenarios are competent guards who also step into a free locker within five metres when something is after them and nothing they know of can see them, and come out after four quiet seconds. They show what the lockers are worth, and nothing asserts on them. It exits non-zero on a softlock (a mascot standing still for 30 seconds, a guard who cannot move, a night that does not end), a guard flattened in the first 30 seconds of night 1, or a bad strategy winning more than one night in ten and more than half as often as playing properly.

The tests in `packages/sim/test` play seventeen of these nights on fixed seeds and compare a summary of each (how it ended, when, the count of each event, and digests of every event and of the final state) with a snapshot. A change to the sim that changes how any of them goes fails `pnpm test`. When the change is meant, `pnpm test -u` rewrites the snapshots, and their diff shows which nights moved and how.

Where the rules stand, over 40 nights a row:

- A competent guard alone wins nights 1 to 5 about 55, 45, 33, 10 and 0% of the time. A careless guard wins 8% of night 1s. The expert script wins 55% of night 1s, half of night 3s and 5% of night 5s.
- Crews of 2, 3, 4 and 6 win 73, 78, 85 and 85% of night 1s, 43, 50, 38 and 43% of night 2s, 35, 8, 10 and 28% of night 3s, 0 to 18% of night 4s and 0 to 10% of night 5s. They lose the power on 0 to 30% of nights 1 and 2 and 20 to 55% of nights 3 to 5, where a guard alone loses it on 0 to 25%. Before a crew got fewer faults and paid less for doors and bangs (`FAULT.crew`, `crewDraw`, the pile-up in `drainPower`) it lost the power on 30 to 98% of its nights and a crew of four won 10% of night 1s. What still ends a crew's later nights is the mascots: each guard is flattened 0.7 to 1.9 times a night, and from night 3 crews of three and four win least. Open for tuning.
- Ignoring the faults loses every night. One guard fixing them while three stay in the booth wins a fifth of night 1s (the harness allows half of what a crew playing properly wins) and none of night 3s.
- A third to a half of faults are left to burn on night 5, and a tenth to a quarter on night 1.
- A competent guard who is caught had a mascot in sight or earshot for a median 5 to 12 seconds first, and under 1.5 seconds one time in fourteen or less.
- The torch runs dry about once in three nights per guard on nights 3 to 5, and a sixth to two fifths of a competent guard's flattenings happen with it dead.
- A competent guard who also ducks into lockers wins about as often as one who does not (58, 33 and 3% of nights 1, 3 and 5, against 55, 33 and 0%), and so does a crew of three (10 and 3% of nights 3 and 5, against 8 and 3%). A guard who steps in is pulled out about one time in four. It was over half while a mascot that had just lost sight still knew the locker and checked two nearby at even odds. Sitting in lockers all night loses every night.
- Competent and expert guards throw their Mini Biggs where its song will draw off a wanderer in their way or a mascot hunting them, while the torch has two fifths left over after the bar it costs, and straight at one coming for them from between 6.2 and 9 metres off (`BONK` in `harness.ts`, the nearest a throw can stun a mascot walking at them), or at Stompy winding up or charging, on whatever battery is left. At one nearer than that they throw for the song. They go back for it once it has had six seconds to work and nothing they know of is moving near it. They throw about two a night each. Per throw, about 0.7 of a mascot goes to the song, and a quarter to two thirds of the throws stun one, most for a guard alone. Before mascots hunting a guard listened to the song and a hit stunned, they threw under one a night. Over 40 nights the change took a guard alone from 43% of night 2s to 73% and from 30% of night 3s to 45%, and crews of three, four and six from 30%, 25% and 25% of night 1s to 43%, 45% and 35%. Crews on later nights did not move. Forty nights puts about eight points of noise on each of those. A crew that shuts itself in the booth with one each to throw at anything near the doors loses every night, and so does one that stays by the carton with the doors open and throws at everything that comes (`x4 toy spam from the booth`).
- The strategies that must lose lose every night 3. On night 1 one runner with three staying in wins 20% (a crew of four playing properly wins 85%), and the rest win none.

## HUD, input and the screens around a night

`three/hud.ts` draws the HUD as HTML over the canvas, styled by the "in the night" block of `styles.css`. It stays at the edges:

- Top left: the hour, the night, and building power. The bar turns yellow under 25% and red under 10%, and reads "Power out" at zero.
- Top left, under the power: the task list. One row per open fault, nearest first: the room, the job and the seconds before it burns. A row turns red for the last 15 seconds and says "burning" after that. The row of the box your hands are in has a green edge. With no faults open it says so.
- Top centre: a compass. Each open fault is a yellow mark with its walking distance, the nearest one filled, red and blinking in its last 15 seconds. A mark points at the next corner of the route there (`route` in `map.ts`), not through the walls, because nobody knows the building on their first night. Flat teammates are red marks with a name, and a blue mark leads to the booth charger once the torch is under 25%. A mark past the end of the strip sits at that end with an arrow. Labels that would overlap are laid side by side under their marks (`spread` in `hud.ts`).
- Under the compass: toasts for events. Each kind has its own icon and colour (`TOAST_ICON` in `hud.ts`, the `.ts-f-toast.is-*` rules in the stylesheet), and the lines are in the `SAY` table in `app.ts`.
- Top right: the other guards and the room each is in. A flat one is red and tagged, and one in a locker is tagged `locker`.
- Bottom left: the torch as a five-bar battery. Grey is off, yellow is on (the torch or the phone), red and blinking with a red glow in the corner is under 25%. Stamina is a thin bar above it that shows only while it is not full. Under the torch, whether your Mini Biggs is in hand, what a throw costs (a bar) and the key, greyed out with empty hands or less than a bar left.
- Centre: the prompt for whatever is in reach, with a bar for the ones that need holding.
- In a locker, the picture is seen between dark slats with the edges closed in, and the dot is gone. The slats are drawn in the scene (`three/slats.ts`), after the rest of the world (its glows too) and before the held phone and torch, so the hands stay in front of the doors and the lights outside stay behind them.

A flattened guard gets a panel saying who did it and how far the nearest standing guard is, and two things to do. Q (or the button) sends a `call` action. The room emits a `call` event at most every `F.CALL_GAP` seconds, and everyone else hears two notes, reads a toast and sees that guard's compass mark pulse. Space steps through the standing guards' views (`player.me.watch`, drawn by `spectate` in `app.ts`) and back to your own. The watched guard's body, name tag and lens glow are not drawn while you look out through their eyes. With "Watch teammates from behind" on in the pause panel (`prefs.third`), the camera follows 3 m behind and above them instead, drawn in front of walls and shut doors and kept under the ceiling, and they are drawn as usual. A guard in a locker is not drawn on anyone's screen (`guard.ts`), and their own camera stands just inside the doors (`LOCKER_LOOK` in `player.ts`).

Input is in `three/player.ts`. The mouse is captured on the first click. Esc releases it and opens the pause screen: the way back and a fullscreen button on the left, and tabs on the right for the controls, the settings (look sensitivity, invert-Y, "Highlight things you can use" and "Watch teammates from behind when you are flat", kept in `localStorage.tsFloor`) and the gamepad. Its size comes from the stage, not the window (a CSS size container), so it fits a Discord Activity's short frame. The night does not stop. The mouse is released for the screens between nights so their buttons can be clicked. A standard gamepad works: left stick walks, right stick looks, A uses, X is the torch, B is the phone and d-pad up zooms its map, RT throws a Mini Biggs, LB runs, Y calls, RB watches, Start pauses. On a keyboard it is G, or the right mouse button.

`three/touch.ts` adds touch controls once a finger touches the screen, or from the start on a device with no fine pointer. A touch on the left 45% of the screen puts a stick under that thumb. A drag anywhere else looks. Use is held, the torch and phone buttons toggle, a Map button zooms the phone's map while it is up, the Biggs button throws a Mini Biggs where the view points (drag to look at the floor first for a short throw) and greys out with empty hands or without the battery for a throw, and Run stays on until the stick is released. Pause and fullscreen sit in the top right corner. The layout is landscape, and a phone held upright is asked to turn. The stage fills the window up to 21:9.

The lobby lists the rules, where every guard reads them while the others join. In the night there are no tutorial tips: the toasts only say what just happened, and the controls are on the click-to-play panel and the pause screen.

The end screens are in `ui.ts`. They read `S.tally` (this night) and `S.total` (the run), which `sim.ts` fills: faults fixed and faults left to burn, who was flattened and by which mascot, and who peeled someone up.

## Sound in the building

`three/sound.ts` gives every sound a place. The listener is this guard's head. A mascot, another guard, the generator, the charger and each one-off event (a fault, a fix, a bang on a door) plays into an emitter: a low-pass filter, a panner with distance rolloff, and a send to the reverb that falls off more slowly than the sound, so far things are more echo than source. It builds no second audio graph. The recipes are `sample()`, `tone()`, `noise()` and `boom()` from `audio.ts`, run inside `into(node, fn)` so they land in an emitter and not straight on the limiter. `main.ts` plays only the win jingle, which has no place in the building.

Walls dull sound. Every 0.13 seconds an emitter asks `sees()` whether the listener has a line to it. If not, `doorwaysBetween()` counts doorways along the shortest way, a shut door counting double, and the `OCC` table turns that into a gain and a low-pass frequency. The panning is plain left-right (`equalpower`), because HRTF measured about twenty times the cost per source. Left-right panning cannot say "behind", so sounds behind the listener lose their top end.

What you can tell by ear:

- Which mascot. Footsteps fire by distance covered (`STRIDE`), so they keep time with its real speed. Big Biggs is a low boom and a slow heavy foot. Madame Flan is a dragging hem and pearls clicking, quiet, and quicker when nobody is watching her. Squish is a wet slap, or sheet metal while it is in the ducts, and it gulps. Stompy is hooves, five a second at a charge. Rot makes all of them lower and wetter.
- What it is doing. Breath (`BREATH`) speeds up when it hunts. `spot` has a sound per mascot (`SPOT`) and a short hit if it is you it saw. A mascot held in a beam growls in short pulls and its costume creaks. `roar` and `crash` are Stompy winding up and hitting a wall. `bang` and `arrive` come from the door they happen at.
- What the mascots as a group are doing. `stir` is a groan through the reverb alone and `calm` a long creak. Nothing on screen marks either.
- Lockers: a sheet-metal clank and a latch from the locker when anyone gets in or out, a rattle when a mascot checks an empty one, and a wrench and a slam when it pulls someone out (`locker`, `check` and `found`). A mascot that catches a guard at a breaker box makes the noise it makes on seeing one, with the same hit for the guard it caught (`startle`).
- Mini Biggs: the squeak of its belly and a swish from whoever throws one, then a thump where it lands, a click, and two lines of Happy Birthday from a crushed three-bit voice box that drags and sags in pitch as the charge runs out, until the last note is a groan (`toy`, `song()` in `audio.ts`, made once into a buffer so the whole song is one voice), a louder squeak and a soft thump when one hits a mascot (`bonk`, and the mascot recoils as Stompy does off a wall), and a squeak when someone picks it up (`grab`). The mascots hear the same thing you do, so you can follow one to it by ear.
- The other guards: footsteps, torch clicks, a fixed fault's clunk, relay and bell, a battery picked up, the two notes of a flat guard's `call`, all from where they are.
- The building: a room tone that is lower and louder in bigger rooms (`SIZE`), a mains hum that sags and stops on `out` and comes back on `on`, the generator's ratchet and dynamo, the charger's hum, the door motors (found by comparing `S.doors` between frames, since the `door` event does not say which), a bell for the hour, a pop and thud where a `fault` breaks out, a crackle from every open fault every two or three seconds so it can be found by ear, and a buzzer for `burn`.

Your own body is not placed: footsteps on the camera's bob, panting under 40% stamina, the torch switch, a buzz on each dip of a dying torch, and ticks while a use is held.

Being flattened plays a stinger hung on the catch's timings (`CUES` in `actors/scare.ts`): a hit at the grab, the mascot's growl at the face (pitched per mascot, `GROWL_RATE`), lower at the bite, then the floor. From then `muffle()` in `audio.ts` closes a low-pass over the whole mix, heartbeat included, until you are peeled. Inside a locker it closes part way (`IN_LOCKER`), so the building is heard through steel. Another guard going flat is a splat, a falling whistle and three bubbles, from where it happened.

The heartbeat, the dread drone, the wind and the far-off oddities are still `ambience()` in `audio.ts`, driven from `main.ts` by `app.threat()` and `dreadF(S)`. `sound.ts` plays no heartbeat or drone of its own.

One-shots are counted (`voices()` in `audio.ts`) and cut from the graph when they end. Past 32 new ones are dropped, and past 18 footsteps and other texture are skipped first. With `?debug`, `ts.floor.sound.stats()` returns the live voices, the always-running sources and the emitters. Nothing is built until the audio context is running, and events that arrive before that are dropped, not queued.

## The building, its light and the picture

`three/world.ts` puts the Depot together from the files in `three/world/`:

- `surfaces.ts` and `tex.ts` paint every floor, wall and ceiling with the 2D canvas when the game loads: a colour map, a normal map from a height canvas, and a roughness map. Each room has its own set (`LOOK`), so one torch-lit patch of floor says which room you are in. A wall texture covers the full height of its room, so dados and damp sit at real heights.
- `art.ts` draws what is stuck on the walls: the posters and the mural of the mascots in their friendly days, staff notices, stains, and the room names. `shell.ts` stencils the name of the next room over each doorway, beside it in a low room, or on the floor where the door fills the wall.
- `shell.ts` builds the geometry from `walls()`, `slabs()` and `DOORWAYS` in the sim's `map.ts`, so the picture cannot drift from the collision. Skirting, door frames, pipes, the stage's arch and the lamp housings go into one mesh (`geo.ts`). The stage platform is 12 cm high and nobody climbs it. The game is flat.
- `props.ts` stands the two prop kits (`models/props_a.glb`, `props_b.glb`) where the sim's `dressing.ts` says. Static props in a room that share a material are merged into one mesh. A kit that has not been built leaves its props out.
- `usable.ts` is the breaker boxes (door hanging open, sparks and a red lamp while faulted, and an orange point light on the nearest three open faults), door buttons, generator, charger, batteries, booth doors and wall map. Each is a plain stand-in until its kit model loads.
- `sight.ts` works out which rooms can be seen from the 2 m square of floor the camera is in, by casting a fan of rays over a grid of the walls, and keeps the answer. Props and usable things in every other room are hidden. three.js culls what is outside the view, not what is behind a wall, and without this the booth draws the kitchen.

`packages/sim/src/dressing.ts` is plain data. `map.ts` imports it to fill `OBSTACLES`, which is how the room walks mascots round furniture without loading a model. After moving a prop or a waypoint, run `pnpm test`. `packages/sim/test/floor-plan.test.ts` fails if a doorway, a waypoint, a breaker box, a button, a battery spot, a locker's doors, a resting mark or a spawn point is blocked or cut off. A locker placed anywhere but the booth is a hiding place, so give it a metre of clear floor in front.

The building's lamps are not three.js lights. `light.ts` bakes them at load into 168 by 176 floor-plan textures, one texel per 25 cm, with the walls casting soft shadows and each room getting some of its own light back as bounce. Every `MeshStandardMaterial` in the scene is patched (`lit`) to look its light up by world position, so mascots, guards and props get it too. The steady lamps are one texture in colour. The second holds four groups, one per channel: two kinds of flicker, a tube that is mostly dead, and the exit signs, which have batteries. A third holds the glow of props with lit screens, baked once the kits have loaded and only for props that did. A group flickers by changing one uniform. With the power out the steady and flickering groups go to zero and the exit signs, the breaker boxes' lamps and the torches are all there is. A fourth texture, two texels a metre, is a mask of how much light each room is getting (`roomMask`): it stutters while a fault in the room is open and drops to almost nothing once `darkRoom` says the room is dark; the exit signs ignore it. To add a lamp, add a row to `LAMPS` in the sim's `data.ts`.

The same patch adds two terms no spotlight gives. One is a little spill round the torch, so a mascot standing beside the beam is a shape. The other is a trace of night vision within a couple of metres, so the dark is not one flat value. The torch itself (`player.ts`) gets a cookie texture with a hot centre and the reflector's rings, and dust that shows only inside the beam. Held close to a wall the beam would bleach it, so the exposure stops down as the lit surface comes nearer than five metres (`GLARE_FROM`). That is what makes a notice readable at arm's length.

Real lights in the scene: the local torch (the only shadow caster, and its shadow pass is skipped while it is off), three point lights that move to the nearest open faults, and whatever `actors.ts` gives other guards' torches. With `?debug`, `ts.floor.renderer.info` counts a whole frame. With one prop kit loaded a frame is 70 to 140 draw calls with the torch off and up to about 300 with it on, because the shadow pass draws every caster in the beam a second time. About 30 of those are the building, up to 50 are props and usable things, and the rest are mascots and guards.

`three/post.ts` draws the scene into a half-float buffer and finishes it in one full-screen pass: exposure, ACES tone mapping, a vignette, grain, and colour fringing at the edges. Dread (`dreadF`, which fills through each night and starts higher on later ones) drains colour, tightens the vignette, thickens the fog and makes the lamps sag. Threat (`app.threat()`) adds grain, fringing and bands of the picture slipping sideways. The grain goes on after tone mapping with a small lift under it, which keeps black areas from being one flat value on a laptop screen. The CSS grain on `.ts-stage` is off while a night is drawn.

Usable things get a gold outline, like the highlight in some games' accessibility modes, so they read as something to walk to in the dark (`three/outline.ts`). Open faults pulse gold, red in their last 15 seconds, wherever they can be seen; flat teammates are red; batteries, the crank, the charger and door buttons are a faint gold within 6 metres; and whatever the use key would act on gets the widest, brightest edge. The pause panel's switch turns it off (`prefs.outline`, on by default). Only while something is marked, `post.ts` draws those meshes again, flat, into a mask (they go on layer 7 under `scene.overrideMaterial`, each setting its colour as it is drawn), and drops any fragment the scene's depth texture puts behind a wall. The full-screen pass edges the mask with eight taps at up to three widths and lays the edge over the finished picture, after tone mapping, so it shows in the dark. The torch's shadow is not redrawn for the mask.

Quality is `high` or `low` (`QUALITY` in `post.ts`). High draws at up to 1280 pixels across with a 1024 shadow map, low at 854 with a 512 map and no fringing. The game starts on high, times sixty frames once the shaders have compiled, and drops to low if they average over 26 ms. `?q=low` or `?q=high` in the URL fixes it.

## Mascots, other guards and the catch

`three/actors.ts` owns everything that moves and is not you. The work is in `three/actors/`.

The room sends positions ten times a second. `track.ts` keeps each actor's last eight snapshots, stamped with `S.t`, and draws the actor one and a half send intervals in the past, between two of them. Easing toward the latest snapshot would lag by an amount that depends on speed. The track also reports the distance covered each frame, and the walk runs on that.

The models are trees of rigid named parts with no armature (`tools/models/README.md` is the contract). `rig.ts` finds the parts by the name the file gave them and holds an offset from rest for each. Nothing is keyframed. Each frame `mascot.ts` adds layers to those offsets and writes them once:

- The gait. A foot is on the ground for half the cycle and goes back at ground speed, so it stays where it landed. The length of a step is the leg's swing plus the turn of the hips, and with hips a metre across the turn is about a third of it. That is the waddle. Squish at stage 2 floats, Flan at stage 2 glides, and the stage 1 crouchers crawl or hop (`gait.mode` in `styles.ts`).
- The pose of the state. A pose is one number per channel (`CH` in `styles.ts`: lean, jaw, each arm, how hard it shudders). Every state has one, and the channels spring toward the pose of the current state, so a change of state cannot pop. A torch beam lays the `lit` pose over roam, search and hunt.
- Head and eyes. The head turns to the nearest standing guard within its limits, the eyes make up the rest, and every beat or so there is a chance it looks somewhere else. At stage 1 the head moves in held steps.
- Kicks: short moves set off by events. The hit on a door lands with `bang`, the lunge comes when a beam leaves a hunting mascot, the recoil with `crash`.
- What only one of them has (`chains` in `styles.ts`: Flan's legs, Stompy's worm, Squish's spine, the mask in Biggs's mouth), then anything named `sway_`, on a damped spring.
- Feet planted: the legs take back whatever the body did above them.

`styles.ts` is the tuning: per mascot and stage, the gait, the limits from the model's notes in `public/models/<key>.json`, and the poses. To change how a mascot stands in a state, change its pose there.

A mascot with no model yet is a stand-in built from the same named parts, so it moves by the same rules. The next rot stage is loaded as soon as the current one shows. When `m.rot` changes, each screen swaps the model only while it cannot see the mascot: a wall is in the way, or it is off the edge of the picture. Dark does not count, since its eyes still show. One you keep looking at stays as it was until you look away.

Materials named `eye_glow` are drawn unlit and without fog (`loadActor` in `assets.ts`), and each gets a soft point drawn over it that never shrinks below a few pixels, so an unlit mascot is a black shape with two pale points at any distance. Mascots the camera has no line of sight to are hidden and not animated.

`guard.ts` is another guard: `guard.glb`, walking on the same rule, head and torch arm following their pitch, flattened by a spring that overshoots and peeled with a pop. A name shows within 7 m and in sight, or within 25 m when the guard is flat. Only the two nearest lit torches are real spotlights; the rest are a glowing lens. With the phone up a guard's left arm comes forward with a phone in the hand and a green glow on it, and their torch arm drops. `hands.ts` holds the `flashlight` from `props_a.glb` in front of the camera.

`plush.ts` draws every Mini Biggs in `S.toys`: a lob from the thrower's hand, tumbling, then on the floor sat up and rocking with the tune while a red light in its tummy blinks, slower as the cell gives out, then tipped over on its back until someone picks it up or the night ends. On the floor it gets the faint gold outline while your hands are empty. It is built from a few spheres and a cone with the colours in the vertices, one mesh and a light each.

`phone.ts` is your own phone: a late-90s candybar built from boxes in code, with a stub aerial, a green-lit keypad and a hand round it, at the bottom left of the view. Its screen is a canvas from `three/minimap.ts`, redrawn eight times a second like an old green LCD. Near, it is about 26 metres across, centred a little below the middle on you, and turns with you so that ahead is up, with an N at the edge. R zooms out to the whole building with north up. It shows the rooms and doorways, shut booth doors in red, other guards (a grey cross for a flat one), the open faults (blinking amber), the generator and the charger, spare batteries, and every mascot off its mark as a red blip, the same mascots the booth's wall map shows.

`scare.ts` is the catch, from the `flat` event for this guard. For a second and a half the camera is taken to the mascot's face (`face` in the manifest; the worm's mouth for Stompy at stage 2) while the mascot plays its `scare` pose, then dropped to the floor as it lets go. The room has the mascot walking off by then, so `mascot.ts` draws it where it stood for the catch and eases it back afterwards (`hold`). A 2D canvas over the 3D one strobes and tears the frame, and does neither under `prefers-reduced-motion`. The cues are `CUES` in that file: `grab` 0, `face` 0.12, `bite` 0.62, `drop` 1.05, `floor` 1.3, `end` 1.5 seconds. `app.actors.scare.listen((cue, by, seconds) => ...)` calls back as each passes, and `app.actors.scare.now` is `{ by, t, cue }` during a catch.

## Recordings

Doors, bangs, footsteps, creaks, wind and growls are recordings in `public/sfx`. The hum, heartbeat and chimes are synthesised in `audio.ts`, because they change with dread and threat as you play. The sounds you play by (footsteps, door motors, bangs, growls) have a synthesised stand-in that plays if the file has not loaded.

- `hit_low`, `hit_long`: [Horror hit soundpack 1](https://opengameart.org/content/horror-hit-soundpack-1) (OpenGameArt)
- `steps*`, `creak*`, `wind`, `scare_growl`, `far_growl*`: [Free horror SFX](https://liminal-space-dev.itch.io/free-horror-sfx-sounds) by Liminal Games (itch.io)

A bang on a shut door is one of four layered recipes in `BANGS`, picked at random. Recordings pass through a generated room reverb (`room()`), with more of it for sounds that are further away.
